# DDR5 IDD Typical-vs-Max Current Research (Item 4 / T4-10)

Primary sources fetched and text-extracted directly (via WebFetch + PDF text extraction, or via the r.jina.ai text-extraction proxy where direct binary fetch timed out/exceeded size limits) on 2026-09-05. Every claim below is tied to one of these extracted documents; where a claim rests only on a proxy-mediated extraction I could not independently re-verify byte-for-byte, this is flagged explicitly.

## (a) Do vendor datasheets publish a typical (non-max) IDD figure, or only spec-limit max?

**Finding: only spec-limit max/"current limit" values were found in every Micron datasheet checked. No typical/nominal IDD column exists in these documents.**

- Micron, "16Gb DDR5 SDRAM Addendum: MT60B4G4, MT60B2G8, MT60B1G16, Die Revision A," Doc. No. CCM005-0005-1684161373-30, Rev. D, Feb. 2023 (this is the exact document already cited as ref [29] in the book) — fetched via `https://r.jina.ai/https://www.mouser.com/datasheet/2/671/16gb_ddr5_sdram_diereva-3193781.pdf`. The IDD table (Table 6, "DDR5 IDD, IPP, IDDQ Current Limits – 16Gb Die Revision A") carries a note stating: *"Maximum values for IDD currents considering worst-case conditions of process, temperature, and voltage."* There is no "Typical" or "Typ." column anywhere in the table.
- Micron, "16Gb DDR5 SDRAM Addendum: MT60B4G4, MT60B2G8, MT60B1G16, Die Revision D," Doc. No. CCM005-1684161373-39, Rev. E, 01/2024 — fetched directly and text-extracted with pymupdf from `https://static6.arrow.com/aropdfconversion/315b38de807c111e26056d39f175f3d134429ca8/mt60b1g16hd-56b.pdf` (I verified this myself from the raw extracted PDF text, not just a proxy summary). Table header is literally "DDR5 IDD,IPP,IDDQ **Current Limits**" — again only one column of values, no "Typ." column anywhere in the ~2,700 lines of extracted text (`grep -i "typical\|typ\."` returns zero matches in this document).
- SK hynix module-level datasheets checked (see (d) below for chip-vs-module caveat) — "DDR5 SDRAM U-DIMM Based on 16Gb M-die," Rev. 1.0 / Mar.2021 (`https://gzhls.at/blob/ldb/b/e/5/8/5bc212f7c92604fd3737505ee4c96014733c.pdf`) and "DDR5 SDRAM SO-DIMM Based on 16Gb A-die," Rev. 1.1 / Jul.2022 (`https://www.uttc.com.tw/wp-content/uploads/2025/12/DDR5_SoDIMM_16Gb_A-die_based_Rev.1.1.pdf`) — both text-extracted directly with pymupdf. Their IDD tables list a single mA value per parameter per speed grade with no "Typ"/"Max" column label visible in the extracted text at all (the note above the table only says module IDD is derived from PMIC 5V input current); I could not confirm from extractable text whether these single values represent typical or max, so I do **not** claim these are typical values — only that no explicit typical/max distinction is stated in the extracted text.

**Conclusion for (a):** No real typical/nominal IDD figure, distinct from a max/limit figure, was found in any Micron datasheet checked (which explicitly and repeatedly label their sole IDD column "Current Limits" / "Maximum values ... worst-case"). This confirms the book's current assumption for Micron. No SK hynix chip-level IDD table with an explicit typ/max label was located (see (d)); the SK hynix module-level datasheets found provide only a single unlabeled current figure per parameter, which is a different ambiguity than "typical exists but book uses max" — it means the label is simply not stated in what I could extract.

## (b) Is there a real IDD6 value in a Micron or SK hynix DDR5-4800 datasheet?

**Finding: Yes for Micron — a real IDD6N and IDD6E value at DDR5-4800 was found in the Micron Die Revision A datasheet (ref [29], the document the book already cites for other IDD parameters). No IDD6 value at DDR5-4800 was found in the Micron Die Revision D datasheet (it doesn't cover DDR5-4800 at all) or in any SK hynix chip-level datasheet.**

- **Micron 16Gb DDR5 SDRAM Die Revision A** (Doc. No. CCM005-0005-1684161373-30, Rev. D, Feb. 2023 = book's ref [29]), Table 6 "DDR5 IDD, IPP, IDDQ Current Limits – 16Gb Die Revision A", DDR5-4800 column, x4 width:
  - **IDD6N (0–85°C) = 102 mA**
  - **IDD6E (85–95°C) = 200 mA**
  - Both are explicitly labeled max/worst-case limits (see (a)). Note: this figure was obtained via the r.jina.ai text-extraction proxy on the Mouser-hosted copy of this exact document (direct WebFetch of the Mouser PDF timed out three times); it is corroborated by an independent search-engine text-snippet extraction of the same document that also reported "102 mA" for IDD6N(0-85C) x4, so I have reasonable confidence in the number, but I was not able to open the raw PDF bytes myself to triple-check it the way I did for the Die Revision D document below.
- **Micron 16Gb DDR5 SDRAM Die Revision D** (Doc. No. CCM005-1684161373-39, Rev. E, 01/2024) — I extracted this document's full text myself directly (pymupdf on the raw PDF fetched from `static6.arrow.com`). Its IDD6 table only covers **DDR5-5600, DDR5-6400, and DDR5-7200** — DDR5-4800 does not appear anywhere in this document (`grep "4800"` returns zero hits). At DDR5-5600/6400: IDD6N(0-85°C) x4 = 112 mA, IDD6E(85-95°C) x4 = 186 mA (DDR5-7200 values are "TBD" in this datasheet). These are **not usable as a DDR5-4800 IDD6 source** since the speed grade doesn't match.
- **SK hynix**: I was unable to obtain a verified numeric IDD6 value from a genuine SK hynix chip-level "16Gb DDR5 SDRAM" component datasheet. I located what appears to be the correct chip-level document — "DDR5 SDRAM 16Gb DDR5 SDRAM Lead-Free&Halogen-Free (RoHS Compliant)" a.k.a. `Consumer_CP16GD5_H5CG4486AGBDJXxxx_Rev.1.0.pdf` and its `Rev.1.1_1anm` successor, hosted at `https://www.uttc.com.tw/wp-content/uploads/2025/12/` (found via `https://www.uttc.com.tw/download/`) — but both files exceed the 10 MB WebFetch size cap and the r.jina.ai proxy returned empty content for both, so I could not extract their IDD6 table. This is an explicit **not found** for a verified SK hynix chip-level IDD6 number. The two SK hynix *module*-level datasheets I could read (U-DIMM Rev.1.0/Mar.2021, SO-DIMM Rev.1.1/Jul.2022) do list an "IDD6N" row at DDR5-4800 (e.g., 63.8 mA for an 8GB 1Rx16 U-DIMM, 126.1 mA for a 16GB 1Rx8 U-DIMM, scaling with module capacity/rank), but these are **module-level PMIC-input currents covering the whole DIMM (DRAM + RCD + PMIC efficiency losses)**, not a single 16Gb chip's IDD6, so they cannot be used as a substitute for the missing chip-level number.

**Conclusion for (b):** A real, chip-level, datasheet-sourced Micron IDD6 value at DDR5-4800 exists — **102 mA (IDD6N, 0–85°C, x4)** from ref [29] itself — and is markedly lower than the current 12 mA NVMain placeholder is *not* comparable to (see recommendation). No equivalent SK hynix chip-level number was recoverable.

## (c) What does JESD79-5 itself say about typical vs. max IDD?

I obtained the JEDEC committee ballot draft "DDR5 Full Spec Draft Rev0.1" (Committee JC42.3, Item 1845.31A, dated 12/5/17; header on every page reads "Proposed DDR5 Full spec (79-5)") from `https://static.mr-wu.cn/doc/JESD79-5%20Proposed%20Rev0.1.pdf`, and text-extracted it directly (321 pages, pymupdf). **Caveat: this is a pre-ratification 2017 JC42.3 committee ballot/proposal draft, not a purchased/registered copy of a finalized, JEDEC-published JESD79-5/79-5A/79-5B/79-5C revision** — I was blocked from the finalized JEDEC standard text by JEDEC's registration/access wall (jedec.org lists JESD79-5D as the current document but does not serve full text without registration or purchase). The draft is nonetheless a genuine JEDEC committee document and its structure for this section is unlikely to have changed in later ratified revisions, but I cannot confirm that with certainty.

From Section 11, "IDD and IDDQ Specification Parameters and Test Conditions" (page 303 of the draft):

- Table 126, "IDD and IDDQ Specification Example," has a single value column headed **"IDD Max."** for every IDD symbol (IDD0 through IDD8) — there is no "IDD Typ." column anywhere in this table.
- Table 128, "IDD6 Specification," carries these notes verbatim:
  - NOTE 2: *"Max. values for IDD currents considering worst case conditions of process, temperature and voltage."*
  - NOTE 4: *"Supplier data sheets include a max value for IDD6."*
  - NOTE 6: *"Refer to the supplier data sheet for the value specification method (e.g. max, typical) for IDD6E and IDD6A"*

**Conclusion for (c):** The JEDEC standard's own template does define the *concept* of typical vs. max informally (NOTE 6 acknowledges vendors could specify either method for the extended-temperature and auto-self-refresh IDD6 variants), but the standard itself **only publishes a numeric "Max." column** for IDD6 (and every other IDD parameter) and explicitly states that vendor datasheets provide a max value for IDD6 (NOTE 4). JESD79-5 does not itself carry vendor-fillable numeric IDD tables with real numbers in this draft — the numeric cells are blank/"TBD" placeholders for vendors to fill in their own datasheets; JEDEC defines only the test conditions, measurement-loop patterns, and the "Max." reporting convention. This matches, and helps explain, why both Micron datasheets checked in (a)/(b) publish only a "Current Limits"/max column and never a typical column: they are following the JEDEC template's own convention of a max-only table.

**Finding: a real chip-level SK hynix "16Gb DDR5 SDRAM" datasheet was located, but only its revision label (not an internal publication date) could be confirmed, and confidence that it is the exact same product as ref [30] is moderate, not high.**

  - `Consumer_CP16GD5_H5CG4486AGBDJXxxx_Rev.1.0.pdf` — Revision 1.0
  - `Consumer_CP16GD5_H5CG448＆6AGBDJXxxx_Rev.1.1_1anm.pdf` — Revision 1.1 (marked "1anm", i.e. a later "1a nm" process/die-shrink variant of the same part family)
  - Both are listed on that page as component/chip-level datasheets (as distinct from the R-DIMM/SO-DIMM module datasheets also on the same page), and the document title text surfaced in search results reads "DDR5 SDRAM 16Gb DDR5 SDRAM Lead-Free&Halogen-Free (RoHS Compliant)" — i.e., the product name matches "16Gb DDR5 SDRAM" (ref [30]'s exact title) rather than a SODIMM/RDIMM module title.
  - The part-number prefix "H5CG44/48/86AGBDJ" also matches SK hynix's chip-level component part-numbering convention (H5xx = bare DRAM component), distinct from the "HMCGxx" prefix used on the module-level UDIMM/SODIMM datasheets I was able to read in full (see (a)/(b)).
- **I could not open either PDF's actual content**: both exceed the 10 MB WebFetch size limit, and the r.jina.ai text-extraction proxy returned empty content for both URLs (likely also hitting a size or timeout limit on their end). So I cannot confirm an internal cover-page date (e.g. "Rev. 1.0 / Mon.Year" as printed inside the document, the format SK hynix uses on its module datasheets). The only "date" I have is the distributor's own upload timestamps on uttc.com.tw (December 2025 for Rev.1.0 and the Rev.1.1_1anm file, January 2026 for an unrelated 32Gb M-die datasheet) — **this is the mirror site's upload/hosting date, not the datasheet's own publication date**, and should not be used as if it were.

**Confidence level: moderate.** The product title and chip-level part-number convention are consistent with ref [30]'s "16Gb DDR5 SDRAM" chip-level product, but I could not read the document to (i) confirm it isn't actually a different density/organization variant misfiled under this name, or (ii) recover the genuine internal revision date. **No confirmed year/revision for ref [30] can be reported with high confidence from this research.**

## (e) Recommendation for the book

1. **The IDD6 = 12 mA NVMain placeholder should be corrected, but not by simply swapping in the number found here.** A real, datasheet-sourced Micron IDD6 value now exists — **IDD6N = 102 mA (0–85°C, x4, DDR5-4800, max/worst-case) from ref [29]** (Micron 16Gb DDR5 SDRAM Die Revision A, Doc. No. CCM005-0005-1684161373-30, Rev. D, Feb. 2023 — the same document already cited in the book) — and it is roughly 8.5x higher than the current 12 mA placeholder. Since ref [29] is already in the bibliography and already used for the book's other max-limit EIDD figures (EIDD2P0/EIDD2P1, etc.), using this same document's IDD6N figure keeps the book's existing sourcing methodology (spec-limit max, single vendor per figure) internally consistent rather than introducing a new methodology just for this one parameter. Note the x4-width caveat: if the project's config models a different data width (x8/x16) or a different Micron die revision, the exact IDD6N value would differ and should be re-checked against the correct width column in the same table (Die Revision D's higher-speed data show IDD6N does not scale trivially between widths/speeds, so don't assume linear scaling from the x4/4800 figure alone).
2. **No usable SK hynix chip-level IDD6 counterpart was found**, so the book cannot currently produce a symmetric hynix-floor/Micron-ceiling pair for IDD6 the way it apparently does for EIDD3P (115.94 mA hynix-derived vs. 151.45 mA Micron-derived). Until the SK hynix chip-level datasheet content is actually read (the two candidate files at uttc.com.tw were located but not opened — worth a follow-up attempt via a source that isn't size-capped, e.g. requesting the file split into byte ranges, or trying SK hynix's own registration-gated portal directly), the book should either (a) use the Micron-only IDD6N=102 mA figure with a footnote that no second-vendor IDD6 figure could be sourced, or (b) keep disclosing IDD6 as unsourced-for-hynix specifically, rather than unsourced entirely.
3. **The book's disclosed limitation ("datasheet IDD values are specification limits rather than typicals") needs no correction — this research confirms it is accurate, and can now cite primary support.** Every Micron IDD table checked (Die Rev A = ref [29]; Die Rev D) explicitly and exclusively labels its values "Current Limits" / "Maximum values ... considering worst-case conditions," with zero typical-current columns present. The JEDEC JESD79-5 draft template itself (Section 11, Table 126/128) also defines only an "IDD Max." column and states in NOTE 4 that "Supplier data sheets include a max value for IDD6" — i.e., the max-only convention traces back to JEDEC's own template, not a Micron- or SK hynix-specific choice. The one nuance worth adding to the disclosure: JEDEC's own NOTE 6 acknowledges that for the *extended-temperature/auto-refresh* variants specifically (IDD6E, IDD6A) a vendor could in principle report either "max" or "typical" — so the limitation should perhaps say "vendor datasheets we could access report IDD as specification-limit maxima; JEDEC's own template permits (but does not require) a typical value for a subset of IDD6 variants, and we found no case of a vendor exercising that option" rather than implying typical values are categorically unavailable across all of JEDEC's framework.
