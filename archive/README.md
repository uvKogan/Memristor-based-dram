## Reproducibility snapshot policy (added cycle 7, 2026-07-12)

The cycle-6c independent verification found that on-disk `.config` files can
silently drift from what actually produced a banked `results/` generation,
with no way to detect it after the fact (see
`results/cycle6c_independent_verification_report.md`). Starting with
`system_v3`, every results generation gets a `configs_used/` subdirectory
snapshotting the exact `.config` files consumed by that run (all technology
configs + both DDR5 band variants, clearly labeled) — a plain file copy
taken immediately around the simulation batch, no new tooling required.
`system_v2_2` got a best-effort retroactive reconstruction (see
`results/system_v2_2/configs_used/README.md` for what could and couldn't be
recovered). Any future generation directory under `results/` should follow
the same convention before being archived.
